## Что представляет собой продукт

RentZal помогает человеку без постоянной команды найти отдельную спортивную игру и занять место. Предмет бронирования — участие в готовом игровом слоте, а не аренда всего зала. Это главное отличие, на котором построен лендинг.

Подтверждено исходниками:
- Каталог с фильтрами по спорту, району и диапазону дат: `apps/web/src/pages/SlotsPage.tsx`, `apps/api/internal/handlers/routes.go:191`.
- Футбол, баскетбол, волейбол, теннис в фильтре интерфейса. Наличие конкретной игры зависит от каталога; демо-данные содержат футбол, баскетбол, волейбол.
- Карточка слота: площадка, адрес, дата, длительность, число свободных мест, ожидаемая цена, правила: `SlotDetailsPage.tsx`, `SlotCard.tsx`.
- Регистрация и вход, каталог доступен без авторизации; личный кабинет защищён: `apps/web/src/App.tsx:83`.
- Бронирование с проверкой статуса слота, дедлайна, повторной записи и вместимости: `routes.go:21`.
- Раздел «Мои участия»: `MyParticipationsPage.tsx`, `apps/api/internal/handlers/me.go`.
- Имитация оплаты: в обработчике создаётся запись и меняется статус на PAID, реальный провайдер не вызывается. Это также прямо указано в README.

Стек основного приложения: React + TypeScript + Vite, React Router, Tailwind, Axios; Go REST API, PostgreSQL, Redis, Docker Compose. Документация местами отстаёт от реализации: описание авторизации только демо-токенами уже неполно, в коде есть JWT и регистрация.

## Замечания к текущей реализации

1. **Статус участия теряется при перезагрузке карточки.** `SlotDetailsPage.tsx:22` всегда начинает с NONE; загрузка получает только слот, не восстанавливая участие. После обновления страницы забронировавший пользователь снова видит кнопку брони. Нужно получать текущий статус участия и обновлять данные слота после записи.
2. **Бронирование может сообщать успех при ошибке БД.** `routes.go:106–122` игнорирует ошибки Begin, Exec и Commit. Нужны проверки каждого шага и успешный ответ только после подтверждённого commit. При ошибке Begin возможен вызов метода у nil-транзакции.
3. **Авторизацию нужно подготовить к публикации.** `auth.go:16` содержит фиксированный ключ JWT; middleware сохраняет вход через X-Demo-Token. Ключ нужно вынести в конфигурацию, а демо-вход отключать вне локальной среды. Секрет в этот отчёт не копируется.
4. **Идентификатор пользователя повторно хешируется.** JWT хранит UUID зарегистрированного пользователя, но Join, Pay и Me преобразуют его через NewMD5. Так участие связывается с дополнительной записью пользователя, а не исходным аккаунтом. При дальнейшей разработке следует нормализовать идентификацию.
5. **Публичный адрес ещё не задан.** Пользователь подтвердил локальный запуск. Лендинг предупреждает перед переходом в локальный каталог; после размещения приложения достаточно поменять единый адрес в конфигурации лендинга.

Это статический обзор для подготовки лендинга, а не полный аудит. Исходное приложение не изменялось.

## Решения для лендинга

- УТП: «Твоя игра. Твои люди. Твоё место». Дополнительный посыл: «Приходи один. Играй вместе».
- Сохраняются три предоставленных SVG, фирменная палитра #B9F227 / #10161D / #F4F6F1 и шрифт Inter.
- Figma и PDF содержат брендбук, а не готовую страницу. Композиция лендинга разработана заново в рамках брендбука.
- Структура: первый экран → три шага → возможности и демонстрационная карточка → люди и спорт → FAQ → финальный переход в продукт.
- Карточка помечена как пример; цены и места не выдаются за живую афишу. Не используются выдуманные отзывы, количество пользователей, гарантии возврата, мгновенная реальная оплата или ссылки на магазины приложений.
- Лендинг независим от API. Никакие бронирования и платежи с него не отправляются.
