## Проверка размещения

По [официальной документации](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), GitHub Pages раздаёт статические файлы и сохраняет IP-адреса посетителей в целях безопасности. Это происходит независимо от согласия на Метрику. Подготовленный Node.js-сервис подтверждения согласия на GitHub Pages не выполняется.

[Политика GitHub](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement) предусматривает международную обработку данных. Подтверждения размещения баз данных посетителей конкретного сайта в РФ нет. Геолокация IP-адреса CDN не доказывает место хранения журналов.

Часть 5 [статьи 18 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/cbf4e15b7c330f9372e876cdf2bc928bad7950ef/) устанавливает ограничения на использование зарубежных баз данных при сборе персональных данных граждан РФ. Баннер согласия не является исключением из этих требований. Для юридического вывода о конкретной схеме надо установить роли участников и фактические операции с данными; проверка сайта не заменяет такую оценку.

Практический вариант для подготовленной реализации: разместить лендинг и сервис согласий на выбранном владельцем сервере в РФ, проверить условия провайдера, его журналы и резервное копирование, настроить HTTPS и ограниченный доступ к журналу. Исходный код можно продолжать хранить в GitHub; журнал согласий в репозиторий не попадает. Для публичного запуска также уточнить необходимость уведомления Роскомнадзора, меры защиты и процедуры работы с обращениями.
